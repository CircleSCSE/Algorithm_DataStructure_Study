# 석유 시추 : 자료구조, BFS

- 실수
  - 그러니까… 계속 걸리는 문제인데.
  - x, y 가 각각 행, 열에 해당한다.
  - 내가 알던거랑 반대라는 것이다. y = 1이면, 좌표 상에서 x축에 평행한 직선이라는 개념이 나에게는 박혀있다.
  - 그런데 코딩에서는 반대다. y = 1이라는 건 그냥 1열 전체라는 뜻이다. 걍 외워라.
  - y = 1이면 1열 전체다.
  - 즉 y 범위를 저장한다는 건, 그 대상이 걸쳐있는 열의 범위를 저장한다는 것이다.
  - land[2][3] 이면, 2행 3열이다.
  - 애초에 변수명에서 x대신 r ( row ) , y대신 c ( column )를 쓰자. 그래야 안 꼬일 듯
  - 행은 우측으로 쭉 찌르는 느낌, 열을 아래로 쭉 찌르는 느낌
  - 방문 표시의 경우 앞으로 방문할 노드의 값을 바꿔줘야 한다. 방문 이전의 값을 바꾸는게 아니라.
- 공부
  - 문제 읽고 나면, 문제 사이드 접고 코딩해라.
  - 몰랐던 것들을 적으니까 역시 흡수가 된다. 원래라면 증발해서 또 똑같은 부분이 막혔을 곳에서, 떠올라서 해결했다. 실수한 부분들을 적어서 흡수해라. 그러면 흡수율 오른다. 나중에 안 봐도 된다. 그냥 적는 것 자체에 힘이 있다.
  - 길이를 변수에 저장하고 나면, 인덱스는 1칸이 어긋나있으니 그대로 범위를 넣으면 초과가 뜬다. 마지막은 빼줘야 한다.
  - 코드 길어지면 cmd + f 로 찾아라.
  - 그리고, for { 이거 열린 이후에 닫히는 부분 찾을 때, { 옆에 마우스 클릭하고, 아래 화살표로 쭉 내려서 찾자.
  - 특정 라이브러리 쓰는데, push 에 해당하는게 뭔지 기억 안 나면, 넣는 코드 하나 잡고, insert, push_back 다 넣어보고 모니터링해라.

  - 이번 문제는 방문 기록은 똑같은 방식으로 한다.
  - 그런데 값의 누적은 별도의 벡터를 구성하여 해결했다.
- 정답 코드
  - 이런 식으로, 스크롤 맨날 위 아래로 해서 번갈아보며 해야하는건 별도 페이지로 만들어서 옆에 켜서 할 수 있게 하자.
  - 어차피 옆에 누르면 다시 토글로 전환하기 쉬우니까.
  ```cpp
  #include <string>
  #include <vector>
  #include <queue>
  #include <iostream>
  #include <set>

  using namespace std;

  int solution(vector<vector<int>> land) {
      int answer = 0;
      int n = land.size();
      int m = land[0].size();
      queue<pair<int, int>> q;
      vector<int> dr = {1, -1, 0, 0};
      vector<int> dc = {0, 0, 1, -1};
      vector<int> oil_sum(m, 0); // 각 열마다 캘 수 있는 석유의 합을 저장할 배열

      for (int i = 0; i < n; i++) {
          for (int j = 0; j < m; j++) {
              if (land[i][j] == 1) {
                  int count = 1;
                  set<int> c_range; // 열(column)의 범위를 저장
                  q.push({i, j});
                  c_range.insert(j);
                  land[i][j] = 0; // 시작점 방문 처리

                  while (!q.empty()) {
                      int r = q.front().first;
                      int c = q.front().second;
                      q.pop();

                      for (int z = 0; z < 4; z++) {
                          int mr = r + dr[z];
                          int mc = c + dc[z];
                          if (mr < 0 || mr >= n || mc < 0 || mc >= m) {
                              continue;
                          }
                          if (land[mr][mc] == 1) {
                              q.push({mr, mc});
                              count++;
                              c_range.insert(mc); // 방문한 곳의 열(c)을 기록
                              land[mr][mc] = 0; // 큐에 넣을 때 방문 처리
                          }
                      }
                  }

                  // 탐색이 끝난 덩어리의 크기를 해당 덩어리가 걸쳐 있는 모든 열에 더해줌
                  for (int col : c_range) {
                      oil_sum[col] += count;
                  }
                  // 방문처리를 하면서 0으로 만들기 때문에
                  // 그냥 샌 것들을 더하기만 하면 된다.
                  // set 자료구조도 for문으로 돌릴 수 있다.
                  // 그리고 oil_sum 자체가 각 열에서 관통해서
                  // 추출할 수 있는 크기를 누적하는 것이다. 별도의 벡터를 만든 것임.
              }
          }
      }

      // 가장 많은 석유량을 찾기
      for (int i = 0; i < m; i++) {
          if (oil_sum[i] > answer) {
              answer = oil_sum[i];
          }
      }
      // 마지막에 oil_sum에서만 최댓값 찾으면 된다.
      return answer;
  }
  ```
- 실수 조언
  - 잘못된 방문 처리 위치 및 시점 (Core Dumped의 직접적 원인)
    - BFS 내부를 보면 새로운 좌표를 큐에 넣을 때 land[x][y] = 0; 을 수행하고 있습니다. 즉, 새로 찾은 인접 좌표(mx, my)를 0으로 만드는 것이 아니라, 이미 꺼낸 현재 좌표(x, y)를 0으로 만들고 있습니다. 새로 큐에 들어간 좌표들은 여전히 land에서 1로 남아있게 되므로, 다음 탐색이나 다른 인접 칸에서 해당 칸을 또 발견하고 큐에 계속 중복으로 집어넣게 됩니다. 큐가 무한히 팽창하여 메모리가 터지는 것입니다. 또한, 처음 탐색을 시작하는 i, j 위치도 큐에 넣을 때 0으로 방문 처리를 해주어야 합니다.
  - 시작 노드 카운트 누락
    - 석유 덩어리의 크기를 세는 count 변수가 0으로 시작합니다. 큐에 새로운 좌표가 들어갈 때만 count가 증가하므로, 탐색 시작점인 i, j가 카운트에서 빠지게 됩니다. count는 1로 시작해야 합니다.
  - 행(Row)과 열(Column) 범위 혼동
    - 문제에서 시추관은 수직으로 떨어집니다. 즉, 석유 군집이 어느 열(Column)들에 걸쳐 있는지가 중요합니다. 현재 코드는 x_range에 행 좌표인 i와 mx를 넣고 있습니다. 시추관이 뚫고 지나가는 기준은 열이므로 j와 my를 기록해야 합니다.
